# 水墨笔触（`mo.js`）

**这一套是半成品，不是能直接开新片的完整画风。** 2026-10 做《一个人想着一个人》墨戏版时写的核心层，用来验证「纯 canvas 上能不能做出像样的水墨笔触」。核心层能用，但**画面设计那一层失败了**，所以只把核心收进资源库，配套的场景/人物/构图没留。

## 一句话结论（想做水墨 MV 的话先看这段）

水墨的门槛在**少**。一笔下去就是一座山——画面上大部分地方必须是空的纸。
那次失败的原因就是我把它当成了「用墨画的普通插画」：一个镜头里塞进床、椅子、台灯、桌子、相册，观众看到的是**一间杂物间**，而且相机一推，每个镜头露出的东西还不一样，认不出是同一个房间。

**正确的做法**：一个镜头只画一样东西，画大，其余全是纸。人物只在需要「有人在」的时候出现，而且往往只画一个背的剪影留在画面一角。

## 能用的部分：`mo.js`

一个 `MoLayer` 管一帧的墨。用法：

```js
const L = new MoLayer(W, H, 1 / 3, ctx);   // W/H 成片尺寸，1/3 是浓淡图的比例（省 9 倍像素），ctx 是主子画布
L.stroke(pts, { w: 22, ink: .85, wet: .4 });   // 一笔
L.curve(ctrl, { w: 22, ink: .85, smooth: 8 }); // 一笔（给控制点，自动平滑）
L.bleed(cx, cy, R, { ink: .3, wet: .9, age: t - t0, rate: 2 });  // 一团墨化在纸上
L.blob(outline, { ink: .9 });                  // 一块实心的墨（剪影）
L.gap(pts, 7);                                 // 在已画的墨里抠掉一条细缝（露出纸色）
L.develop({ ink: [26,24,21], soft: .5, rim: .5, fade: 1 });      // 收尾：啃边 + 积墨 + 上色，铺到主画布
```

### 它做对了什么

1. **笔触不是等宽的线**。`stroke()` 沿路径按弧长取点，宽度走「起笔顿、行笔饱、收笔细」，浓度收笔变淡（飞白）。等宽黑线一眼就假。
2. **边缘是啃出来的**，不是描出来的。`develop()` 拿两层噪声（大颗粒定形状、细颗粒做毛感）去啃 alpha 边缘，然后在边缘内侧补一圈更浓的墨（水把墨推到纸上边上的「湿边」）。**这一啃一补是水墨看着活的关键**。
3. **`gap()` 留缝**。人物糊成一坨就是因为手臂和身体之间没有纸色。水墨画人物，靠的就是笔与笔之间的缝，不是靠描边。
4. **`bleed()` 的晕**。边缘不圆（一圈抖动的边）、越靠外越淡、边上那圈更黑。
5. **确定性**。全部随机数走 `moRng(seed)`（xorshift），同一秒永远画出同一笔，所以本机和云端、不同机器渲染结果一致，可以跳帧、可以分段并行。

### 性能

1080p 一帧约 400～600 ms（1/3 浓淡图 + 一次全图啃边/积墨）。50 秒 30fps 的片子本地跑约 15～20 分钟，能接受但不算快。想快就把 `R` 降到 1/4，或者把啃边和积墨合并成一次遍历。

### 已知的坑

- `MoLayer` 每帧 new 一个（里面 3 张画布）。**别在循环里复用**，`clear()` 有个 setTransform 的坑。
- `willReadFrequently: true` 必须开，否则 `getImageData` 每次都慢一倍。
- 相机变换要在 `_plot` 之前设到 `L.P` 上（见失败项目里的 `applyCam`），因为它直接往浓淡图上画。

## 顺带学到的：火山识别的「编时间」问题

写 `align_two_asr.py` 是因为发现了火山语音的一个坑，**以后凡是唱得很快的连续短句都得防**：

带歌词原文当上下文（`--ctx`）时，它**不会漏字，但会编时间**。实测它把 2.2 秒里按每字 0.04 秒硬塞了 30 个字（那 2.2 秒根本唱不完 30 个字），又另起一段把后半句重复列了一遍，看起来像整段唱了两遍——**实际只唱一遍**。

做法：**不带上下文那份当基准**（时间准、段切得对），**带上下文那份只用来补漏掉的字**。工具用法见 `../tools/lyrics/align_two_asr.py` 开头。

判断某一段是不是被编了时间的快速办法：看那段里每个字的时长中位数。实测正常的段在 0.16～0.36 秒，被编的那段中位数是 0.04 秒。
